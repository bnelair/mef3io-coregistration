# mef3io-coregistration 0.3.1

*Released 2026-10-21.*

## Highlights

- **Compressed results.** Results, clock maps and recording mappings can be
  saved gzip-compressed: give the file a name ending in `.gz`
  (`subject01.coreg.json.gz`). Every reader detects compression from the
  content, whatever the file is called, so a renamed download still opens.
  Decompression is bounded, so an upload cannot exhaust memory. New `CoregResult.to_bytes(compress=...)` and
  `CoregResult.from_bytes(...)` for results held in memory (uploads, web
  downloads), and `mef3io_coregistration.io.jsonfile` for any of these files.
  ([Result format](https://bnelair.github.io/mef3io-coregistration/result_format/))
- **Reopen a saved result.** `CoregSession().open_result(path)` reopens a
  result's recordings (checked by their time span, as always) and its clock
  map without re-running the stages, to read through it or save it again.
  ([Read a coregistration in Python](https://bnelair.github.io/mef3io-coregistration/howto/read_python/))
- **A mapping finds its result in either form** (`x.coreg.json` ↔
  `x.coreg.json.gz`), next to the mapping or where it named it, and picks the
  copy whose content is the saved result.

## Fixes

- Opening other recordings in a `CoregSession` now forgets the previous
  pair's alignment (its clock map used to survive `open()`).
- A file with a byte-order mark (saved by some Windows editors) opens; a
  damaged file is refused with a clear `ValueError`.

## Upgrading

Nothing changes for existing files: every result and mapping saved by 0.3.0
opens unchanged. The hash a mapping stores for its result is now of the JSON
content; for plain `.json` results that is the same hash as before.

Full list of changes: [v0.3.0...v0.3.1](https://github.com/bnelair/mef3io-coregistration/compare/v0.3.0...v0.3.1)
